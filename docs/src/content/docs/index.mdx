Runcoil runs your functions as durable background Tasks. You write a Task as a normal Go function and wrap each piece of work in a Step. The server saves the result of every Step, so a crash, a deploy, or a retry does not repeat the work that already finished.

You host Runcoil yourself. It is one server and PostgreSQL, with nothing else to run.

:::caution
**Runcoil is in early development.** Expect breaking changes until the first release. [What works today](#what-works-today) lists the parts you can use now.
:::

## How it works

Your Task code runs in your own process, called a worker. The server keeps the state of every Run and decides which worker runs it.

<CrashReplay />

1. Your worker starts and connects out to the Runcoil server. The server never calls into your network.
2. A Run of the Task `process-order` is queued in PostgreSQL.
3. The server sends the Run to a worker with a free slot.
4. The worker runs your handler. Each Step reports its result, and the server saves it.
5. The handler returns. The server marks the Run `succeeded` and keeps its output.

If a worker stops in the middle of a Run, the server puts the Run back in the queue, and the next attempt can run on another worker. The handler runs again from its first line, and each Step that already finished returns its saved result instead of running again. In the diagram, worker-a is lost during Step 3, and worker-b returns Steps 1 and 2 from their saved results, then runs Steps 3 and 4. [Lost connections](/concepts/workers/#lost-connections) says when the server decides that a worker is gone.

## A Task in Go

A Task is a function with a JSON input and a JSON output. Wrap each side effect in `step.Do`:

```go
func processOrder(ctx context.Context, in orderInput) (orderOutput, error) {
	chargeID, err := step.Do(ctx, "charge", func(ctx context.Context) (string, error) {
		return charge(ctx, in.OrderID)
	})
	if err != nil {
		return orderOutput{}, err
	}

	_, err = step.Do(ctx, "email", func(ctx context.Context) (bool, error) {
		return true, sendReceipt(ctx, in.OrderID, chargeID)
	})
	if err != nil {
		return orderOutput{}, err
	}

	return orderOutput{ChargeID: chargeID}, nil
}
```

`charge` and `sendReceipt` stand for your own code. If `email` fails, Runcoil runs the handler again later, and `charge` returns its saved result without charging twice. [Steps](/concepts/steps/) explains the replay.

## What works today

- **Workers.** A Go worker registers its Tasks, receives Runs, reconnects after an outage, and drains on shutdown.
- **Steps.** The server saves each Step result, and a Run that runs again skips the Steps already done.
- **Retries.** A failed Step retries with a delay, by its own policy or the server default.
- **Schedules.** A Task with a cron expression gets a Run at each tick.

These parts are not built yet: an SDK call that starts a Run, waits, a dashboard, and API key management.
